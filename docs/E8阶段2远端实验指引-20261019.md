## 3. tmux 运行

```bash
tmux new -s e8p2
cd /root/ZX-GBS/ZX-GBS-PO && source .venv/bin/activate
PYTHONPATH=src python scripts/e8_phase2_run.py --processes 32 \
  2>&1 | tee artifacts/e8_risk_prior/phase2/run.log
# 断开：Ctrl+B 后按 D；重连：tmux attach -t e8p2；中断后同一命令重跑即断点续跑
```

`--processes` 建议 **32**（64 核留半给系统/BLAS 线程）。内存注意：每进程峰值约 3GB
（ρ̂ 词表 535MB + 样本批次 1.6GB + 该折面板/引擎），32 进程 × 3GB ≈ 96GB——
**先确认服务器空闲内存 ≥ 100GB 再开 32 进程**；若只有 64GB，用 `--processes 16`（~48GB）。
若内存不足症状（OOM kill），降 `--processes` 后同命令重跑（已完成折自动跳过）。

## 4. 耗时与内存预估

- 本地（M 系 MacBook）单折四配置串行 ~530s（ρ̂ 词表 18s 一次 + 每折 Q1 链 40s + 4 配置 × δ 网格回测）。
- 服务器 64 核、fold 级并行 20 单元、32 进程：单批 20 折全部并发 → wall time ≈
  单折耗时（服务器单核通常慢于 M 系，按 ~700s 估）+ 启动开销 ≈ **15–25 分钟**。
  16 进程同样一批装下（20 折 > 16 进程则两批 ≈ 25–40 分钟）。
- 内存峰值预估：32 进程 ≈ 96GB + 主进程共享数据 ~3GB。**务必先 `free -g` 确认。**

## 6. 故障排查

| 症状 | 处理 |
|---|---|
| OOM kill / 进程消失 | 降 `--processes`（32→16→8），同命令重跑（断点续跑） |
| `FileNotFoundError: sample_store/hardware/hw-5M-b0/packed.npy` | 数据未就位；检查 `sample_store/hardware/hw-5M-b0/` 存在 |
| pytest 全绿但实验起不来 | 确认 `git pull` 拉到含 risk_prior.py 的最新提交 |
| 某折卡住 | 看 run.log 最后完成的折号；杀掉后同命令重跑自动续 |
| summary.json 未生成 | fold_results.jsonl 为空才有此情况；确认至少一折完成 |
